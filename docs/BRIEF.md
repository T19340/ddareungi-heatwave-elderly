## 1. 대회 사실 (공고·포스터·양식에서 확인)
- 정식 명칭: 데이터로 바꾸는 우리의 이동 — AI와 함께하는 교통문제 해결을 위한 데이터 분석 공모전
- 주최: (재)숲과나눔 풀씨행동연구소, 한겨레신문. 공고: https://koreashe.org/notice/?uid=95427&mod=document&pageid=1
- 접수: 2026-08-18 ~ **2026-10-22(목)**, 이메일 제출((이메일 생략), 제목 [공모전]_팀명). **오늘 10/20, 이틀 남음.**
- 참가: 교통·도시·환경 문제에 관심 있는 개인 또는 3인 이하 팀.
- 공모 주제: 교통문제 해결을 위한 데이터 분석. 활용 데이터: 공공·민간데이터, 시민과학 데이터 등.
- 공고 취지문 핵심 문장: "대중교통이 부족한 지역, 보행과 자전거로 이동하기 어려운 환경, 교통약자가 겪는 불편 등 시민이 체감하는 이동의 격차", "사람 중심의 이동과 지속가능성, 사회적 형평성", "수송부문 온실가스 배출량의 약 97%가 도로교통", "기존 정책에서 잘 드러나지 않았던 교통문제를 발견하고 해결 방안을 모색", "이동의 격차를 줄이고 탄소중립에 기여할 수 있는 정책 아이디어".
- 심사: 1단계 기술성 심사(데이터 활용과 분석 방법의 적절성 등) → 2단계 공익성 심사(문제의 공익성, 정책 활용 가능성 등) → 결선 5팀. 배점 비공개.
- 시상: 대상 1팀 100만 원, 최우수 2팀 각 70만 원, 우수 2팀 각 50만 원.
- 일정: 결선 진출 발표 11월 3주차(개별 연락) → 결선 발표자료(PPT, 주요 코드·실행 결과 포함) 11/27 제출 → 결선 12/2(수) 13:30~15:10, 시상 17:30 연세대 백양누리, 「제8회 숲과나눔 환경학술포럼」 안에서 진행. 팀 전원 참석 필수.
- 결선 청중·심사 추정: 환경·보건·안전 분야 연구자와 활동가(환경학술포럼), 언론(한겨레). 같은 재단의 2022년 생물다양성 데이터 경연에서 분석 리그 1위는 기온·습도와 매미 개체수의 상관을 시각화한 비교적 단순한 분석이었고 평가 사유는 "활용 가치, 실현 가능성"이었다. → 복잡한 모델보다 **문제 발견의 설득력 + 바로 쓸 수 있는 정책 결과물**이 유리하다고 추정(공식 배점 아님).

## 2. 분석보고서 필수 항목 (붙임2 양식 그대로; PDF, 본문 5장 내외, 표지·참고문헌 제외)
1. 이름/팀명, 주제(데이터 분석의 핵심 내용을 파악할 수 있는 주제명)
2. 분석 배경 및 목적: 현황·문제점, 목적, 필요성, 해결하려는 문제 상황, 왜 이 분석이 필요한지·참여 동기
3. 활용 데이터: 표로 제시 — 활용 데이터(명) / 제공기관(명) / 출처 플랫폼(명) / URL 필수 + 선정 이유
4. 분석과정 및 방법: 수집·전처리, 적용 기법과 절차, 알고리즘, 통계분석 방법론
5. **AI 기술 활용**: 사용 서비스, 활용 범위, 주요 프롬프트
6. 분석 내용 및 결과: 상세 내용과 결과·인사이트. **접수 마감일까지 분석을 완료하여 결과를 포함해 제출하는 것이 원칙**
7. 정책제안 및 기대효과: 기대효과·시사점·파급효과, 적용될 수 있는 구체적 사례, 활용 방안 및 적용 대상
8. 분석도구 및 참고문헌(출처 표시 필수)
9. 분석결과 이미지(필수): 시각화·인포그래픽·화면 캡처를 문서 안에 포함
- 코드: GitHub/클라우드 링크를 보고서에 기재. 결선 진출 시 실행 가능한 전체 코드 제출, 발표 때 실행 확인.

## 3. 참가신청서 규정 중 작업에 걸리는 것
- 데이터는 적법 수집. 이용약관·라이선스 준수. **접근권한 우회, 무단 계정 사용, 약관 위배 자동수집·크롤링 금지.** 공식 다운로드 파일이나 공식 API만 쓴다.
- 결과물에 데이터의 출처, 제공기관, 수집 방법, 수집기간 또는 기준시점, 주요 변수, 이용조건을 밝혀야 한다.
- 민간데이터는 분석·출품·결과 공개가 허용되는 범위에서만. 민간 지도 API(카카오·네이버 등)는 약관상 결과 공개 허용 여부를 확인하지 않으면 쓰지 않는다.
- 시민과학·직접 수집 데이터는 수집 주체·방법·기간·지역을 밝힌다.
- **AI 활용 고지 의무**: 데이터 수집·정제·분석·결과물 작성에 AI를 쓰면 서비스명, 활용 범위, 주요 프롬프트를 밝힌다. AI가 만든 결과는 참가자가 직접 검증. 개인정보·비공개 자료를 외부 AI에 입력 금지.
- 표절·대리 제작·**타 공모전 동일·유사 출품 금지**(수상 후 적발 시 취소·환수).

## 4. 공통 작업 규칙 (모든 후보 공통)
### 폴더 규격 (각 후보 폴더 안)
- `SPEC.md` 과제 명세(주어짐). 필요하면 결정 사항을 덧붙여 갱신.
- `data_raw/` 내려받은 원본. **절대 수정 금지.** 하위 폴더는 데이터셋마다 하나씩. 다운로드가 로그인·키를 요구하면 그 사실을 SOURCES.md에 적는다.
- `data_raw/SOURCES.md` 데이터셋마다: 이름 / 제공기관 / 플랫폼 / URL / 라이선스(공공누리 유형 등) / 기준시점 / 다운로드 일시 / 파일명·행수·주요 컬럼 / 알려진 한계(커버리지, 결측).
- `data_proc/` 가공 데이터(CSV/parquet). `code/` 번호 붙인 파이썬 스크립트(`00_download.py`, `10_clean.py`, `20_analysis.py`, `30_figures.py` 식). `figures/` PNG. `results/` 표(CSV)와 수치 요약.
- `STATUS.md` 진행 보고(아래 템플릿). `ai_usage_log.md` AI(이 작업자)가 한 일의 범위 기록(보고서 'AI 기술 활용' 란 작성용): 수집·전처리·분석 설계·코드 작성·시각화·문안 중 무엇을 했고 사람이 검증할 지점이 무엇인지.

### 실행 환경
- Windows 11, Python 3.14.2. 사용 가능: pandas 3.0, numpy, matplotlib, seaborn, scikit-learn 1.8, xgboost 3.2, shap 0.52, statsmodels, scipy, requests, openpyxl. (geopandas·shapely·pyproj는 설치 시도 결과를 BRIEF 끝의 '환경 메모'에서 확인. 없으면 numpy로 하버사인 거리와 좌표 변환을 직접 구현하거나 pyproj만 설치해 쓴다.)
- 실행은 항상 `python -P -E -X utf8 경로/스크립트.py` (스크립트 폴더를 sys.path에 넣지 않음, 환경변수 무시, UTF-8). 데이터 폴더 안에서 인터프리터를 실행하지 않는다. 스크립트는 `code/`에, 데이터는 `data_raw/`·`data_proc/`에.
- 셸은 PowerShell 5.1과 Git Bash. 한글 경로는 그대로 쓴다. 콘솔 출력 인코딩 오류가 나면 `-X utf8`을 확인한다.
- API 키가 필요한 데이터(공공데이터포털 오픈API 등)는 코드에 하드코딩하지 말고 환경변수(`DATA_GO_KR_KEY`)로 읽게 짠다. **키가 없으면 신청 안내(어느 API, 신청 URL, 승인 소요)를 STATUS에 적고, 키 없이 받을 수 있는 파일 데이터 경로를 먼저 찾는다.** 키를 기다리느라 멈추지 않는다.
- 패키지 설치가 필요하면 `python -m pip install --user 패키지`로 시도하고 결과를 STATUS에 적는다.

### 그림 규격
- matplotlib, `plt.rcParams['font.family']='Malgun Gothic'`, `plt.rcParams['axes.unicode_minus']=False`, 150 dpi PNG, 가로 10인치 내외. 제목·축 이름·단위·기준시점·출처 각주를 그림 안에 넣는다. 지도는 산점도(위경도)로도 충분하다. 색은 색각 이상자도 구분되게(viridis 계열 등).

### 정직성 규칙 (가장 중요)
- **데이터가 없으면 가상·합성·예시 데이터를 만들어 돌리지 않는다.** 막히면 대안 경로를 두 개 이상 시도한 뒤 STATUS에 "막힘"으로 기록하고 끝낸다.
- 숫자를 두고 하는 문장(늘었다, 절반이다, 집중된다, 때문이다)은 계산 결과와 대조한 뒤 쓴다. 결과가 가설과 반대면 그대로 보고한다.
- 표본 수 n, 결측률, 지역 커버리지(어느 지자체가 빠졌는지), 기준시점을 모든 결과 표와 그림에 붙인다.
- 상관을 인과처럼 쓰지 않는다. 정책 제안은 "데이터가 보여준 것"과 "거기서 추론한 것"을 나눠 쓴다.
- 이 프로젝트 폴더(`교통공모전_2026`)와 웹 공개 자료만 사용한다. **사용자의 다른 로컬 폴더·문서·메모리 파일은 읽지 않는다.**

### 범위와 시간
- 1차 패스 목표: 데이터 확보 → 핵심 분석 1개 → 그림 2~3장 → STATUS.md. 완벽한 모델보다 재현되는 파이프라인과 솔직한 평가가 중요하다.
- 막힌 채로 오래 끌지 말 것. 데이터 가용성 판정에 1시간 이상 걸리면 그 시점 상태를 STATUS에 쓰고 대안으로 넘어간다.
- 전국 범위가 무거우면 도 1곳·도시 1곳으로 좁힌다(선택 이유 기록).

### STATUS.md 템플릿
1. 한 줄 결론: 유망 / 보통 / 비관 + 이유 한 문장
2. 데이터 확보 표: 필요 데이터 | 확보 여부 | 출처 URL | 기준시점 | 단위·행수 | 문제점
3. 수행한 분석과 예비 결과(숫자 포함, n 명시)
4. 그림 목록(파일명 + 한 줄 설명)
5. 막힌 것, 사용자 조치 필요 항목(API 키 신청 등 — 어디서 무엇을 어떻게)
6. 남은 작업과 예상 소요(마감 10/22 기준)
7. 심사 관점 자체 평가: 기술성 / 공익성·정책 활용 / 차별성(기존 연구·서비스와 무엇이 다른가) / 위험·반론
8. 보고서 '주제명' 후보 2개와 핵심 메시지 한 문단
